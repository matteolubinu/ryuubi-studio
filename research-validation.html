Why I made it

I work alone. Nobody tells me "this idea is weak"

I build iOS apps on my own: no colleague to push back in a meeting, no research team. The real risk isn't ugly code. It's spending weeks on a feature the market already solved better, or that nobody feels as a problem.

When I considered adding vaccine and booster tracking to Refertrack, I did the research with this method before opening Xcode. Two things I wouldn't have found by writing code:

  • Booster schedules aren't the same in every country. Both the interval and the per-vaccine exceptions change. A fixed value in the code would have been wrong by design.
  • The value is knowing what's due, not archiving. The apps praised in reviews get credit for "what's overdue, what's due soon". History comes second.

I used the same method for a competitive benchmark on Quillino, my rental management app. Then I cleaned the file up, made it general, and put it here.

references/test-with-real-data.md

What it is: bonus. A pattern for testing OCR, receipt, PDF or form parsers with real, anonymized data.

How to use it: when your product extracts data from real documents. With a coding agent: “set up parameterized tests for my parser following references/test-with-real-data.md”. By hand: follow the four steps and the checklist.

Input

A real photographed document, anonymized, transcribed exactly as OCR would output it, noise and all: headers, disclaimers, lines to ignore.

Output
Field not recognized → alias missing
from the dictionary. Add it, plus an
explicit test case. Never fix it silently.

Value extracted wrong → parser has an
unhandled case. Extend the sub-parser,
keep old fixtures green.

No. The packs are digital products you download instantly, so there are no refunds. If a file is missing, broken or doesn't match the description, write to quillino.support@gmail.com and it will be fixed.

What if my AI can't browse the web?

The skill says so at the start instead of inventing sources. It works with the sources you paste in, labels everything else as an assumption, and picks up the sourced steps when browsing is available. There's also a quick mode for a first one-page answer.

Can I stop and continue later?

Yes. Every step ends with a short research state summary: paste it into a new conversation and the wizard resumes from there.

Does the skill find sources on its own?

If your AI has web search turned on, yes. Without it, it can't find sources. The method requires direct links, no invented sources, a reliability score for each, and an explicit label when a claim is only an assumption. You still check the sources: findings only start after your review.

Is it only for iOS apps?

No. It works for an app, a feature or a small business. The example is an iOS app because that's what I build.

Which AI do I need?

One with web search, for this pack. It loads as a real skill in Claude, Codex, Cursor, Copilot, Gemini CLI and other tools that support SKILL.md. In ChatGPT or Gemini you paste it as instructions. Without AI, it's a framework you follow by hand.
